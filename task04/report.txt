Пункт 1 та 2:
Було створено застосунок на мові С, який задовільняє вимогам - виводить інформацію про хост середу, час, тощо.
Було розроблено простий скрипт для мінорного спрощення процесу збірки застосунку.
Результати аналізу за допомогою binutils було покладено у відповідний файл binutils_HOST_HOST (збірка на HOST-і під середу HOST-а). 
Можна переглянути такі моменти як архітектуру виконання виконуваного файлу, розмір об'єктів вихідного коду, строкові об'єкти і не тільки.

Пункт 3:
Було модифіковано скрипт для збірки, під застосування aarch64-linux-gnu-gcc для виконання застосунку на target платформі зі встановленим дистрибутивом.
Було запущено такий застосунок на host платформі, результат очікуваний - інтерпретатор повернув повідомлення про невідповідність архітектури ("bash: ./exec_host_target: cannot execute binary file: Exec format error").
Також було застосовано попередні утіліти для аналізу виконуваного файлу, замість ldd довелось використати readelf -d для отримання залежностей.
Вивід таких утіліт у відповідному файлі.

Пункт 4:
Було просто протестовано середу всередині raspberry pi (зазначені утиліти, тощо).
Було клоновано репозиторій та виконано скрипт build.sh (не build_target.sh, фактично використовуємо звичайний gcc, однак так як ця утиліта вже на платформі з арм, отримаємо виконуваний файл під арм).
Також було протестовано роботу застосунків, додано output_target.txt - файл вивіду програми на таргеті; binutils_target_target - вивід утиліт binutils.
